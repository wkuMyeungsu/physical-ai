## 0. 설계 전제

전체 설계에 가장 큰 영향을 주는 세 가지 전제입니다.

### 전제 1. 정면 영상만으로는 거북목을 직접 측정할 수 없다

- 거북목의 표준 지표인 **CVA(두개척추각)는 측면에서 측정**하는 값입니다.
- 정면 카메라로는 간접 신호만 얻을 수 있습니다.
  - 얼굴 크기 대비 어깨폭 비율의 증가
  - 턱과 어깨선 사이 수직 거리의 감소
  - 머리 pitch 변화
- 이 간접 신호는 카메라 높이·틸트·거리(1-5, 1-6, 1-7)에 따라 크게 달라지는데, 현재 대부분 "모름/미정"입니다.
- **→ 개인 캘리브레이션은 선택이 아니라 필수입니다.**

### 전제 2. 거북목 신호와 입벌림 신호는 서로 간섭한다

- 거북목: "얼굴이 카메라에 가까워짐(스케일 증가)"이 **곧 신호**입니다.
- 입벌림: 스케일 변화는 **반드시 제거해야 하는 잡음**입니다.
- 머리를 숙이면(pitch↓), 위에서 내려다보는 카메라 기준으로 입 세로 간격이 짧아 보입니다.

### 전제 3. 추론 장치는 웹캠 내장 NPU (사양 미정)

- 이런 장치는 보통 CPU가 약하고, NPU는 INT8 CNN 연산에만 강합니다.
- **→ 픽셀 단위 전처리는 ISP나 ROI 단위로 최소화하고, 보정은 좌표 단위로 옮기는 것이 기본 전략입니다.**

## 1. 이미지 단위 전처리

| 기법 | 추천 파라미터 | 근거 (현장 조사) | 비고 |
|---|---|---|---|
| **카메라 설정 고정** (AE/AWB 잠금 또는 완만화, 플리커 방지) | 전원 주파수 60Hz(국내), 노출 시간은 1/60s의 정수배, 바른 자세 캘리브레이션 직후 AE 잠금 또는 AE 수렴 속도 저하 | 1-10 자동 설정 "모름", 2-1 형광등·LED 혼재 | 가장 싸고 효과가 큰 단계. 자동 노출이 출렁이면 입술 경계 좌표가 프레임마다 흔들림 |
| **프레임 품질 게이트** | 평균 휘도 < 40 또는 > 220(8bit)이면 판단 보류, 블러(Laplacian 분산)가 베이스라인의 30% 미만이면 스킵 | 2-1 자연광(시간대 변화), 2-6 반사·그림자 "모름" | 불량 프레임은 보정보다 버리는 편이 저렴 |
| **렌즈 왜곡 보정** | 수평 FOV ≤ 70°이면 생략 가능, ≥ 78°이면 필요. 이미지 remap 대신 **키포인트 좌표만 undistort** | 1-3 FOV "미정" | 광각일수록 가장자리 어깨 좌표가 늘어나 어깨폭 정규화가 틀어짐 |
| **ROI 크롭** (원본 해상도에서) | 얼굴 bbox × 1.3–1.5 여유, 입 ROI는 얼굴 하단 40%. 크롭 후 모델 입력 크기로 리사이즈(예: 192–256px) | 1-8 어깨까지 보임, 1-7 거리 "모름" | **반드시 원본 해상도에서 크롭.** 전체 축소 후 크롭하면 입술 간격이 1–2px로 뭉개짐 |
| **롤(roll) 정렬** | 양 눈 중심선이 수평이 되도록 얼굴 ROI를 affine 회전 (±30° 이내) | 1-11 카메라 고정 상태 상이, 1-9 모니터 구성 다양 | 얼굴 랜드마크 모델 정확도를 크게 향상 |
| **ROI 대비 보정 (CLAHE)** | 휘도 채널(YCrCb의 Y 또는 LAB의 L)에만 적용, clipLimit 1.5–3.0, tile 4×4 (얼굴 ROI 기준) | 2-2 광원 방향 제각각, 2-1 천장광 → 코 아래·입 주변 그림자 | 입술 경계·치아 대비 향상. **전체 프레임에는 적용 금지** (창문 역광이 히스토그램 지배) |
| **감마 보정** | 얼굴 ROI 평균 휘도 < 90이면 γ 0.6–0.85, > 180이면 γ 1.1–1.3. LUT로 구현 | 2-1 자연광·스탠드 → 역광·저조도 | 연산 비용 거의 없음. CLAHE가 버거우면 감마만 사용 |
| **노이즈 제거** | 기본은 ISP의 3DNR. 필요 시 얼굴 ROI에 Gaussian 3×3, σ 0.5–1.0 | 2-3 체감 밝기 "보통~밝음" → 심한 저조도 드묾 | Bilateral·NLM은 NPU 환경에서 비용 대비 효과 낮음. 시간축 노이즈는 키포인트 스무딩으로 처리 |
| **화이트밸런스 보정** | 생략 권장 | 2-1 모니터 빛(푸른 색조) | 랜드마크 모델은 주로 휘도 의존. 치아 보임을 색상으로 판단할 때만 gray-world 검토 |
| **모델 입력 정규화** | 학습·INT8 양자화 보정(calibration) 데이터와 **완전히 동일한** mean/std 및 letterbox 방식 | 7-1 온디바이스 NPU | 불일치 시 양자화 모델 정확도 급락 |

## 2. 키포인트 단위 전처리

### (a) 신뢰도 게이팅

- visibility 또는 score **< 0.5인 점은 결측으로 처리**합니다.
- 근거: 1-8 "어깨까지" 조건 → 화면 하단의 어깨는 자주 잘리거나 옷에 가려져 신뢰도가 낮음.

### (b) 좌표 왜곡 보정

- `cv2.undistortPoints`로 **필요한 점(눈, 입술, 턱, 어깨 등 20–30개)만** 보정합니다.
- 근거: 1-3 FOV 미정.
- 내부 파라미터를 모르면 `fx ≈ (W/2) / tan(HFOV/2)`로 근사 가능하나, **제품 단위 체스보드 캘리브레이션 1회**를 권장합니다.

### (c) 이상치 제거

세 가지를 조합합니다.

| 방법 | 기준 |
|---|---|
| 속도 임계값 | 한 프레임 이동량이 어깨폭의 0.15–0.3배 초과 시 이상치 |
| Hampel 필터 | 창 5–7프레임, MAD 기준 k = 3 |
| 구조 일관성 | 어깨폭·동공 간 거리가 베이스라인 대비 ±25% 이탈 시 해당 프레임 의심 |

- 근거: 2-1·2-2 복합 광원 아래 랜드마크 순간 튐이 잦음, 1-11 카메라 미고정 환경에서 카메라 자체 흔들림.

### (d) 결측 보간

실시간 시스템이므로 양방향 보간은 지연을 만듭니다. 결측 길이에 따라 다르게 처리합니다.

| 결측 길이 | 처리 |
|---|---|
| ≤ 200ms (약 3–6프레임) | 마지막 값 유지 또는 등속 외삽 |
| 200ms – 2s | 판단 **보류**, 타이머는 리셋하지 않고 일시정지 |
| ≥ 2s | 해당 구간 무효 처리 및 상태 리셋 |

- 근거: 7-3 지연 1초 이내, 7-4 "확실할 때만".
- 턱 괴기, 컵으로 입 가림, 얼굴 만지기 같은 가림은 입벌림 오탐의 주원인이므로 **반드시 보류로 처리**해야 합니다.

### (e) 스무딩 — One Euro 필터 권장

정지 상태에서는 강하게, 움직일 때는 약하게 걸려 지연이 작습니다.

| 용도 | min_cutoff | beta | d_cutoff | 비고 |
|---|---|---|---|---|
| 거북목용 (어깨, 얼굴 스케일) | 0.3–1.0 Hz | 0.001–0.01 | – | 느린 신호 → 강하게 필터링 |
| 입벌림용 (입술) | 1.0–2.0 Hz | 0.01–0.05 | 1.0 | 빠른 반응 필요 |

- 근거: 7-3 1초 지연 예산. 이동평균 1초 창은 그 자체로 0.5초 지연을 만듭니다.

### (f) 기하 정규화 및 특징 계산

| 용도 | 원점 | 스케일 기준 | 대표 특징 |
|---|---|---|---|
| 거북목 | 어깨 중점 | 어깨폭 (별도로 강하게 스무딩) | 얼굴폭/어깨폭, (어깨선 y − 턱 y)/어깨폭, solvePnP head pitch, 얼굴 절대 스케일 변화율 |
| 입벌림 | 입 중심 | 입 너비 또는 얼굴 높이 | MAR = 내측 입술 상하 간격(2–3쌍 평균)/입 너비, pitch 보정(÷cos pitch 근사), 치아 영역 밝기 비율(선택) |

- 근거: 1-5 "카메라가 눈보다 높음", 6-1 "육안, 전면".
- 카메라가 위에 있으면 거북목 상태에서 얼굴이 **내려가고 + 커지며 + 고개를 숙인 모양**이 됩니다. 이 세 신호를 조합해야 단순히 "모니터에 가까이 다가간 것"과 구분할 수 있습니다.

## 3. 거북목용 / 입벌림용 전처리 분리 여부

### 결론: 분리해야 한다 — 앞단은 공유, ROI 크롭부터 갈라지는 **Y자 구조**

### 분리가 필요한 이유

1. **스케일 처리가 정반대**
   거북목은 얼굴이 커지는 것 자체가 신호이고, 입벌림은 얼굴 크기로 정규화해 그 변화를 없애야 합니다. 같은 정규화를 쓰면 한쪽이 반드시 망가집니다. (1-7 거리 "모름" → 거리 변동 큼)
2. **공간 해상도 요구가 다름**
   어깨·머리 위치는 저해상도 전체 프레임으로 충분하지만, 입술 간격은 화면의 수 % 면적에서 픽셀 단위 정밀도가 필요합니다.
3. **조명 보정 대상이 다름**
   천장광(2-1)이 만드는 코 아래·입 주변 그림자는 입벌림에만 치명적입니다. CLAHE와 감마는 얼굴·입 ROI에만 걸면 됩니다.
4. **시간 특성이 다름**
   거북목은 수십 초~수 분 단위의 느린 변화, 입벌림은 초 단위이며 말하기·하품·먹기 같은 정상 입 움직임과 구분해야 합니다. (예: 1–2초 창에서 MAR 분산·진동이 크면 발화로 보고 제외) 스무딩 강도와 지속시간 판정 모두 따로 둬야 합니다.

### 공유해야 하는 부분

- 카메라 설정, 품질 게이트, 왜곡 보정 계수는 **공통**.
- 머리 **pitch 값**은 거북목 특징이면서 동시에 입벌림의 보정 입력이므로 **양쪽 브랜치에 모두 전달**합니다.

## 4. 최적 적용 순서 (파이프라인)

```
[S0] 카메라/ISP 설정: 플리커 60Hz, AE/AWB 완만화 또는 잠금, ISP 3DNR
 │
[S1] 프레임 획득 + 타임스탬프
 │
[S2] 프레임 품질 게이트 (밝기·블러) ── 불량 → 판단 보류
 │
[S3] 축소 프레임에서 사람/포즈 추정 (어깨·머리)  ※ 저주기 실행 가능
 │
 ├─────────────── 거북목 브랜치 ───────────────┐
 │                                              │
[S4] 원본 해상도에서 얼굴 ROI 크롭 + 롤 정렬     │
[S5] ROI 감마/CLAHE → 모델 입력 정규화           │
[S6] 얼굴 랜드마크 추론                          │
 │                                              │
[K1] 신뢰도 게이팅 (얼굴·어깨 점 모두)  ◄────────┘
[K2] 좌표 undistort
[K3] 이상치 제거 (속도·Hampel·구조 일관성)
[K4] 결측 처리 (유지/외삽 → 보류 → 리셋)
[K5] One Euro 스무딩 (브랜치별 파라미터)
[K6] 정규화 + 특징 계산 (거북목: 어깨 기준 / 입: 입·얼굴 기준 + pitch 보정)
[K7] ★ 개인 베이스라인 대비 편차 (z-score 또는 비율)
[K8] 발화·하품 필터 (입벌림 전용)
[D1] 지속시간 + 히스테리시스 판정 → 알림
```

### 순서가 바뀌었을 때 생기는 문제

| 잘못된 순서 | 생기는 문제 |
|---|---|
| 전체 프레임 축소 → 얼굴 크롭 (S4를 S3 축소본에서 수행) | 입술 간격이 1–2px로 양자화되어 MAR 해상도 소실 |
| CLAHE를 크롭 전 전체 프레임에 적용 | 창문 역광·모니터 빛이 타일 통계를 지배해 얼굴 대비가 오히려 악화, 연산량도 수 배 증가 |
| 롤 정렬 전 CLAHE | 회전 보간 과정에서 대비 강조된 경계에 계단 현상 (차이는 작지만 정렬 먼저가 정석) |
| 스무딩(K5) → 이상치 제거(K3) | 튄 값 하나가 수 프레임에 번져 이상치 검출 불가, 그 사이 오탐 발생 |
| 보간(K4) → 이상치 제거(K3) | 이상치를 근거로 보간값을 만들어 오류 확대 |
| 정규화(K6) → undistort(K2) | 가장자리 어깨 좌표 왜곡이 스케일 기준(어깨폭)에 섞여 모든 비율 특징이 틀어짐 |
| 베이스라인(K7)을 스무딩 전에 계산 | 베이스라인 자체가 잡음을 포함, 30초 데이터 통계가 실제 추론 신호와 불일치 |
| 발화 필터(K8) 없이 판정 | 통화·회의 중 입벌림 알림 연발 → 7-4 "확실할 때만" 요구 정면 위반 |

## 5. 개인 캘리브레이션(베이스라인)

### 위치

- **K6(특징 계산) 직후, 판정 직전인 K7**에 넣습니다.
- 베이스라인은 반드시 **추론 때와 똑같은 S0–K6 파이프라인을 통과한 특징값**으로 만들어야 합니다.

### 근거

- 1-5·1-6·1-7·1-9: 카메라 높이, 틸트, 거리, 모니터 배치를 모르고 환경마다 다르다는 사실을 베이스라인 하나가 한꺼번에 흡수합니다.
- 정면 영상의 거북목 판단은 **"절대 각도"가 아니라 "내 바른 자세 대비 얼마나 변했는가"**로 바꿔야만 성립합니다.

### 30초 촬영(6-4) 운영 권장 사항

- 앞쪽 **3–5초는 버림** (AE 수렴 및 자세 정착 구간).
- 통계는 평균·표준편차 대신 **median과 MAD** 사용 (깜빡임·미세 움직임에 강함).
- 구간 내 분산이 크면 **재촬영 요청**.
- 입벌림용으로 **"편하게 입 다문 상태"**를 별도 확보. 가능하면 **"의도적으로 살짝 벌린 상태" 3–5초**도 함께 받아, 두 상태의 중간값을 개인별 임계값으로 사용. (입술 두께·치열 등 개인차가 커서 고정 임계값으로는 잘 맞지 않음)
- AE 잠금 방식을 쓴다면 **이 시점에 잠금** (이 단계만 예외적으로 이미지 단위 캘리브레이션).

### 재캘리브레이션 트리거

- 근거: 1-11 카메라 고정 상태가 환경마다 다름.
- 어깨폭이나 배경 특징점이 일정 시간 동안 베이스라인에서 크게 벗어나 있는데 자세 변화로 설명되지 않으면, **카메라가 움직였다고 보고 재촬영을 권유**합니다.

## 6. NPU 성능을 고려한 생략 및 경량화

> 가정: 일반적인 웹캠 SoC급 (NPU 0.5–2 TOPS, 약한 ARM CPU)

### 생략 권장

| 단계 | 대체 방법 |
|---|---|
| 전체 프레임 디노이즈 (Bilateral·NLM) | ISP 3DNR + 키포인트 스무딩 |
| 전체 프레임 왜곡 보정 remap | 키포인트 좌표만 undistort |
| 화이트밸런스 보정 | 생략 (휘도 기반 모델) |
| 전체 프레임 CLAHE | 얼굴 ROI 한정 적용 |

### 경량화 권장

- **실행 주기 분리**: 포즈 모델 3–5fps(거북목은 느린 신호), 얼굴·입 랜드마크 10–15fps(1초 지연 요구 충족).
- **검출 대신 추적**: 얼굴 검출은 1–2초에 1회 또는 추적 실패 시에만 실행, 나머지 프레임은 이전 랜드마크로 ROI 갱신.
- **조명 보정은 LUT**: 감마는 LUT 하나로 처리. CLAHE가 CPU에 부담되면 얼굴 ROI 감마만 유지.
- **경량 INT8 모델**: BlazeFace·FaceMesh(또는 PFLD 계열 경량 랜드마크) + MoveNet Lightning급 포즈 모델. 입 영역 전용 소형 모델 분리도 고려.
- **필요한 점만 처리**: undistort·스무딩은 사용하는 20–30개 점에만 적용 (468점 전부 불필요).
- **차선책 — 모델 통합**: 연산이 정말 부족하면 얼굴 랜드마크에서 직접 pitch·스케일을 얻고, 어깨는 저주기 포즈로만 보완.

## 7. 추가 확인 필요 항목

### 🔴 최우선 (설계가 바뀌는 항목)

1. **거북목 정답 확보 수단 (6-1)**
   현재 "육안·전면"으로는 라벨 자체가 부정확합니다. 데이터 수집 시 **측면 보조 카메라를 동기 촬영**해 CVA 또는 귀-어깨 수평 거리를 측정하고, 이를 정면 특징과 매핑해 학습하는 방식을 강력히 권장합니다.
2. **NPU 사양**
   TOPS, 지원 연산자(resize, affine 등), CPU 코어, 메모리, ISP 기능(3DNR, 렌즈 셰이딩, 하드웨어 왜곡 보정 유무). 6장의 경량화 수준이 이것으로 결정됩니다.
3. **해상도·FPS·FOV (1-1 ~ 1-3)**
   1m 거리에서 입술 간격이 몇 px인지가 입벌림 검출 가능 여부를 좌우합니다.
4. **카메라 설정 제어 가능 여부 (1-10)**
   UVC로 AE/AWB 잠금과 플리커 설정이 가능한지 확인이 필요합니다.

### 🟠 중요 (파라미터가 바뀌는 항목)

5. **사용 거리 분포, 카메라 높이 차, 틸트 (1-5 ~ 1-7)** — 정확한 값이 아니라 범위만 알아도 정규화 설계가 가능합니다.
6. **모니터 구성 (1-9)** — 카메라가 보조 모니터에 있으면 사용자가 늘 측면을 보게 되어 yaw가 큽니다. 허용 yaw 범위를 정하고, 넘으면 판단을 보류해야 합니다.
7. **가림 요인** — 안경 반사, 마스크, 수염, 머리카락, 턱 괴기·음료 섭취 빈도, 화면 내 다른 사람 유무.
8. **조명 세부 (2-6, 비어 있는 2-4·2-5)** — 창문 역광 여부와 얼굴 그림자 패턴이 CLAHE·감마 적용 여부를 결정합니다. 조사표의 2-4·2-5와 3~5장이 빠져 있는데, 의도적 생략인지 확인이 필요합니다.

### 🟡 정의가 필요한 항목

9. **입벌림 라벨 기준의 수치화 (6-2)** — "입술 간격 육안"을 예컨대 "내측 입술 간격 ≥ 입 너비의 X%가 Y초 이상"처럼 정량화하고, 발화·하품·식사를 라벨에서 어떻게 처리할지 정해야 합니다.
10. **지속시간과 지연의 관계 (7-3 vs 7-4)** — "1초 이내"가 조건 충족 후 알림까지의 시간인지 확인이 필요합니다.
    - 시작값 제안: 거북목 **30초–2분** 지속, 입벌림 **5–10초** 지속
    - 히스테리시스 적용 (해제 임계값 < 발동 임계값)
    - 실제 값은 사용자 테스트로 결정
11. **조사 규모** — "총 __명, __개 환경"이 비어 있습니다. 베이스라인 방식이 사람 간 편차를 얼마나 흡수하는지 검증하려면 **최소 수십 명, 다양한 조명 조건**이 필요합니다.
