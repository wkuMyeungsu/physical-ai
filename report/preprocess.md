# 거북목 & 입벌림 AI 코치 — 추론 전 영상 전처리 설계안

> **범위**: 카메라 프레임을 받아 모델 입력을 만들기까지, 즉 추론 직전의 영상 처리만 다룹니다.
> 추론 결과의 좌표 처리, 개인 기준 비교, 판정과 후처리는 이 문서의 범위가 아닙니다.
> **기준**: 제품 소개 페이지의 'AI 개발 흐름 ① 전처리' 중 영상 준비 단계(1~5단계).
> **수치**: 경험칙 시작값입니다. 같은 녹화 데이터로 on/off와 값을 비교해 확정합니다.
> **현장 조사**: 응답이 아직 없습니다. 1장의 가정은 응답이 오면 갱신합니다.

## 목차

0. 설계 전제
1. 입력 조건 가정
2. 처리 순서
3. 단계별 처리 (1~5단계)
4. 얼굴 ROI 폭 조건
5. 시제품에서 쓰지 않는 처리
6. 전처리 검증

## 0. 설계 전제

- **온디바이스 연산 예산**: 전처리는 추론과 같은 보드에서 돌아갑니다. 시제품은 RK3566급 SBC로 검증하므로, 전체 프레임에 대한 픽셀 연산은 최소화합니다. 기준 장치의 칩은 미정입니다.
- **원본 해상도에서 얼굴을 잘라야 한다**: 전체 프레임을 먼저 줄인 뒤 자르면 입술 간격이 1~2px로 뭉개져, 입벌림 판단에 필요한 정밀도가 사라집니다.
- **보정은 얼굴 영역에만, 효과가 입증된 것만**: 전체 프레임 보정은 역광이나 모니터 빛이 통계를 지배해 오히려 악화시킵니다. 보정은 얼굴 ROI에 한정하고, 같은 녹화로 효과를 확인한 뒤에만 켭니다.
- **제품의 설치와 사용 조건**: 모니터 상단 중앙, 카메라는 눈높이 이상, 사용 거리 50~80cm(가정값), 수평 화각 약 70~78°, 720p@30fps 운용, 얼굴 정면 ±30° 이내. 마스크·모자·역광 창문은 지원 범위 밖입니다.

## 1. 입력 조건 가정

아래 가정이 현장과 다르면 해당 처리를 바꿔야 합니다.

| 항목 | 시제품 가정 | 가정과 다를 때 |
|---|---|---|
| 해상도·프레임레이트 | 1280×720, 30fps | 해상도가 낮으면 얼굴 ROI 폭이 부족해집니다 (4장) |
| 화각·왜곡 | 수평 70~78°, 저왜곡 | 광각이면 왜곡 처리 방식을 따로 정합니다 (5장) |
| 설치 위치·높이 | 모니터 상단 중앙, 눈높이 이상 | 좌우로 치우치면 얼굴 위치가 한쪽으로 쏠려 크롭 여유를 넓혀야 합니다 |
| 사용 거리 | 50~80cm | 범위가 바뀌면 얼굴 크기가 바뀌어 ROI 폭 조건을 다시 계산합니다 |
| 상반신 범위 | 얼굴과 어깨가 모두 보임 | 어깨가 잘리면 상체 영역 검출이 불안정해집니다 |
| 조명·플리커 | 자연광과 형광등 혼재, 60Hz | 50Hz면 노출 주기를 다시 맞춥니다. 역광은 지원 범위 밖입니다 |
| 자동 노출·화이트밸런스 | 제어 가능 여부 미정 | 고정할 수 없으면 프레임 간 밝기 안정화를 전처리에 넣어야 합니다 |
| 주변 사람 | 단일 사용자 | 다른 사람이 자주 잡히면 크롭 대상을 고르는 규칙이 필요합니다 |
| 착용물 | 안경은 가능, 마스크·모자는 비지원 | 마스크나 모자가 흔하면 얼굴 검출 실패가 늘어납니다 |

## 2. 처리 순서

```
[1] 카메라 설정 고정
 │
[2] 프레임 품질 검사 ──────── 불량 → 프레임 버림 (상위 단계에 보류 신호)
 │
[3] 얼굴·상체 위치 확보 (축소 프레임)
 │
[4] 얼굴 ROI 크롭 (원본 해상도) → 롤 정렬(선택)
 │
[5] 얼굴 밝기 보정(선택) → 모델 입력 정규화
 │
 ▼  모델 입력 (추론 실행은 이 문서 범위 밖)
```

---

## 3. 단계별 처리 (1~5단계)

### 1단계. 카메라 설정 고정

- **무엇**: 전원 주파수에 맞춰 노출 시간을 정하고, 자동 노출과 화이트밸런스는 완만하게 하거나 캘리브레이션 뒤에 잠급니다.
- **시작값**: 60Hz 전원이면 노출 시간을 1/120s의 정수배로 맞춥니다.
- **시제품 기본**: ON (카메라가 UVC 컨트롤을 지원할 때)
- **이유**: 깜빡임과 밝기 출렁임은 프레임마다 얼굴 밝기를 흔들어 모델 입력의 분포를 바꿉니다. 입력을 안정시키는 것이 가장 싸고 효과적입니다.
- **확인 사항**: 노출과 전원 주파수 컨트롤의 지원 여부는 카메라 모델마다 다르므로 제품별로 확인합니다.

### 2단계. 프레임 품질 검사

- **무엇**: 평균 밝기와 흐림 정도를 측정합니다.
- **시작값**: 평균 휘도 40 미만 또는 220 초과(8bit), 또는 블러(Laplacian 분산)가 기준값의 30% 미만이면 불량으로 봅니다.
- **시제품 기본**: ON
- **이유**: 불량 프레임은 보정하지 않고 버립니다. 어두운 화면을 억지로 보정하면 입력이 바뀌어 잘못된 결과로 이어집니다. 불량 프레임은 상위 단계에 "판정 보류" 신호로 넘깁니다.

### 3단계. 얼굴·상체 위치 확보

- **무엇**: 축소한 프레임(모델 입력 크기 640)에서 얼굴과 상체 영역을 찾습니다. 찾은 위치는 다음 프레임에도 이어 씁니다.
- **시작값**: 검출은 1~2초에 한 번, 또는 추적이 실패할 때만 다시 합니다. 검출 주기는 실측으로 조정합니다.
- **시제품 기본**: ON
- **이유**: 위치만 알면 되므로 작은 이미지로 충분합니다. 매 프레임 검출은 연산 부담이 큽니다.
- **대상 선택**: 여러 얼굴이 잡히면 착석 영역 안에서 가장 큰 얼굴을 크롭 대상으로 고릅니다.

### 4단계. 얼굴 ROI 크롭 (원본 해상도)

- **무엇**: **원본 해상도** 프레임에서 얼굴 영역을 잘라 모델 입력 크기(192~256px)로 리사이즈합니다. 여유는 얼굴 박스의 1.3~1.5배입니다.
- **시제품 기본**: ON
- **이유**: 축소본에서 자르면 입술 간격이 1~2px로 뭉개집니다.
- **롤 정렬**: 양 눈 중심선이 수평이 되도록 ±30° 이내에서 affine 회전합니다. 시제품 기본은 OFF입니다. 랜드마크 모델이 롤에 강건하면 생략하고, 필요할 때만 ablation으로 확인합니다.

### 5단계. 얼굴 밝기 보정과 입력 정규화

두 가지를 나눠 봅니다.

**(a) 얼굴 밝기 보정 (선택)**

- **무엇**: 얼굴 ROI에만 대비 보정(CLAHE) 또는 감마 보정을 적용합니다.
- **시작값**
  - CLAHE: 휘도 채널만, clipLimit 1.5~3.0, 4×4 타일
  - 감마: 얼굴 ROI 평균 휘도가 90 미만이면 γ 0.6~0.85, 180 초과이면 γ 1.1~1.3 (LUT로 적용)
- **시제품 기본**: OFF. 같은 녹화에서 효과가 확인될 때만 켭니다.
- **이유**: 전체 화면에 적용하면 역광이나 모니터 빛이 통계를 지배해 얼굴 대비가 오히려 나빠집니다. 감마는 CLAHE보다 가벼우므로 둘 중 하나만 쓴다면 감마를 먼저 검토합니다.
- **주의**: 추론 때만 적용하면 학습 데이터와 입력 분포가 달라집니다. 도입한다면 학습 증강에도 같은 처리를 넣거나, 양자화 보정 데이터에 포함해야 합니다.

**(b) 모델 입력 정규화**

- **무엇**: 입력 크기, 채널 순서, mean/std, 리사이즈 방식을 맞춥니다.
- **기준**: 학습과 INT8 양자화 보정(calibration)에 쓴 설정과 **완전히 같아야** 합니다.
- **시제품 기본**: ON (필수)
- **이유**: 설정이 조금이라도 다르면 양자화된 모델의 정확도가 급락합니다. 이 단계에서 가장 흔한 오류가 생기는 곳입니다.

---

## 4. 얼굴 ROI 폭 조건

모델 입력(192px 이상)을 채우려면, 원본 프레임에서 얼굴 ROI의 폭이 입력 크기 이상이어야 합니다.

`ROI 폭(px) = (W/2) / tan(HFOV/2) × 200mm / 거리`  (얼굴 ROI 실제 폭 200mm 가정)

수평 화각 70° 기준입니다.

| 해상도 | 50cm | 65cm | 80cm | 100cm |
|---|---|---|---|---|
| 1280×720 | 366 | 281 | 228 | 183 (부족) |
| 1920×1080 | 548 | 422 | 343 | 274 |

- 720p는 80cm까지 충분합니다. 사용 거리가 더 멀어지거나 화각이 80°를 넘으면 1080p가 필요합니다.
- 입력 해상도를 높이면 연산이 늘어납니다. 센서 해상도가 ROI 폭 ≥ 입력 크기를 만족하면 그 이상은 이득이 없습니다.

## 5. 시제품에서 쓰지 않는 처리

| 처리 | 상태 | 이유 |
|---|---|---|
| 전체 프레임 CLAHE | 금지 | 역광과 모니터 빛이 통계를 지배합니다. 쓴다면 얼굴 ROI에만 적용합니다 |
| 노이즈 제거 (Gaussian 3×3, σ 0.5~1.0) | OFF | 카메라 내장 처리로 충분하다고 보고, 시간 방향 잡음은 추론 이후에서 다룹니다 |
| 화이트밸런스 보정 | OFF | 랜드마크 모델은 주로 밝기에 의존한다고 가정합니다 |
| 렌즈 왜곡 전체 프레임 보정 | OFF | 광각 렌즈일 때는 이미지 전체를 펴는 대신 필요한 점의 좌표만 보정합니다. 좌표 보정은 추론 이후 단계라 이 문서 범위 밖입니다 |
| 롤 정렬 | OFF (ablation 후 결정) | 랜드마크 모델이 롤에 강건하면 불필요합니다 |

## 6. 전처리 검증

| 확인 항목 | 방법 | 통과 기준 |
|---|---|---|
| 입력 정규화 일치 | 학습 파이프라인과 추론 파이프라인에 같은 이미지를 넣어 입력 텐서를 비교 | 불일치 0 |
| ROI 폭 충분성 | 실제 녹화에서 얼굴 ROI 폭을 측정 | 사용 거리 범위 전체에서 입력 크기 이상 (4장 표) |
| 품질 검사 보류 비율 | 실제 녹화에서 불량으로 버린 프레임 비율 측정 | 보류가 잦아 제품을 쓰기 어려운 수준이 아닐 것 (수치는 실측 후 정함) |
| 보정 on/off 효과 | 같은 녹화를 보정 on/off로 처리해 모델 출력(점 지터, 입술 간격 편향)을 비교 | 개선이 확인된 항목만 켬 |
| 보드 처리 시간 | 1~5단계의 처리 시간을 보드에서 실측 | 프레임 주기(30fps에서 약 33ms) 안에 들어올 것 |
