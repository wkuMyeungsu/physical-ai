# 거북목 & 입벌림 AI 코치 — 데이터 전처리 설계안

> PRD v1.1.0 기준의 이미지·키포인트 전처리 기법, 적용 순서, 캘리브레이션 및 경량화 전략
> 괄호 안의 번호(예: 1-5, 2-1)는 [check_list.md](check_list.md)의 현장 조사 항목 번호입니다.

### 읽는 방법

- **체크리스트 응답은 아직 비어 있습니다.** 이 문서의 "근거" 열은 조사 결과가 아니라 **"이 항목의 응답이 설계에 영향을 준다"는 연결**입니다. 응답이 없는 항목은 **시제품 가정값**으로 대체했고, 응답이 채워지면 가정을 갱신해야 합니다. (7장 참조)
- 표의 수치(휘도 기준, 파라미터 범위 등)는 문헌 근거가 있는 값이 아니라 **경험칙 시작값**입니다. 시작값은 PoC에서 같은 녹화 데이터로 비교해 확정합니다.
- 이미지 보정 기법은 **"시제품 기본" 열이 OFF인 것은 효과가 입증되기 전까지 켜지 않습니다.** (PRD 5.1-7)

## 0. 설계 전제

### 전제 1. 정면 영상만으로는 거북목을 직접 측정할 수 없다

- 거북목의 표준 지표인 **CVA(두개척추각)는 측면에서 측정**하는 값입니다. PRD도 절대 경추 각도 측정을 범위 외로 두었습니다. (PRD 5.2)
- 정면 카메라로는 간접 신호만 얻을 수 있습니다.
  - 얼굴 크기 대비 어깨폭 비율의 증가
  - 턱과 어깨선 사이 수직 거리의 감소
  - 머리 pitch 변화
  - 얼굴 절대 크기의 증가
- 이 간접 신호는 카메라 높이·틸트·거리(1-5, 1-6, 1-7)에 따라 크게 달라집니다.
- **→ 개인 캘리브레이션은 필수입니다.** 판정은 "절대 각도"가 아니라 **"내 기준 자세 대비 변화량"**입니다.
- **→ 이 간접 신호가 실제 거북목(측면 CVA)과 상관있는지는 아직 검증되지 않았습니다.** PRD 7장 미결 사항 1순위이며, 측면 보조 카메라 동기 촬영(6-1)으로 가장 먼저 확인해야 합니다. 실패하면 2장 (g)의 특징 구성과 PRD 5.1-1을 다시 정의해야 합니다.

### 전제 2. 거북목 신호와 입벌림 신호는 서로 간섭한다

- 거북목: "얼굴이 카메라에 가까워짐(스케일 증가)"이 **곧 신호**입니다.
- 입벌림: 스케일 변화는 **제거해야 하는 잡음**입니다.
- 고개를 숙이면(pitch↑) 입 세로 간격이 짧아 보이고, 고개를 돌리면(yaw) 입 너비가 짧아 보입니다. 그 크기는 2장 (f)에서 따집니다.

### 전제 3. 추론은 온디바이스 NPU, 칩은 미확정 (PRD 4장)

- 양산 후보 SoC는 PoC 결과로 결정하고, **시제품은 RK3566급 SBC**로 알고리즘을 검증합니다.
- NPU는 INT8 CNN 연산에 강하고 CPU는 상대적으로 약하다고 가정합니다. 카탈로그 TOPS가 아니라 **목표 모델의 실측 지연**으로 판단합니다. (6장)
- **→ 픽셀 단위 전처리는 ISP나 ROI 단위로 최소화하고, 보정은 좌표 단위로 옮기는 것이 기본 전략입니다.**

### 전제 4. 시제품의 사용 조건 (PRD 5.3, 5.4)

| 항목 | 기준 | 관련 체크리스트 |
|---|---|---|
| 사용자 | 단일 사용자 | – |
| 설치 | 모니터 상단 중앙, 카메라 높이 눈높이 이상 | 1-4, 1-5 |
| 사용 거리 | 50~80cm (**가정**) | 1-7 |
| 카메라 | 수평 화각 약 70~78°, 720p@30fps 이상, 무왜곡 렌즈 | 1-1, 1-2, 1-3 |
| 상반신 | 얼굴과 어깨가 모두 보임 | 1-8 |
| 얼굴 방향 | 정면 ±30° 이내 (벗어나면 판정 보류) | 1-9, 5-2 |
| 가림 | 가려지면 판정 보류 | 4-2, 5-4 |
| 비지원 | 마스크, 모자, 역광 창문 | 2-2, 4-2 |

## 1. 이미지 단위 전처리

| 기법 | 시작값 (경험칙) | 시제품 기본 | 관련 체크리스트 | 비고 |
|---|---|---|---|---|
| **카메라 설정** (AE/AWB, 플리커) | 전원 주파수 60Hz, 노출 시간은 일반적으로 60Hz 전원 조명의 깜빡임 주기(1/120s)의 정수배, 캘리브레이션 후 AE 완만화 또는 잠금 검토 | **ON** (카메라가 UVC 컨트롤을 지원할 때) | 1-10, 2-4, 2-5 | 자동 노출이 출렁이면 입술 경계 좌표가 흔들립니다. UVC 카메라에서 노출·전원 주파수 컨트롤 지원 여부는 제품별로 확인이 필요합니다. |
| **프레임 품질 게이트** | 평균 휘도 < 40 또는 > 220(8bit)이면 판단 보류, 블러(Laplacian 분산)가 베이스라인의 30% 미만이면 스킵 | **ON** | 2-1, 2-3, 2-4, 2-6 | 불량 프레임은 보정하지 않고 버립니다. PRD의 판정 보류 조건과 연결됩니다. |
| **렌즈 왜곡 보정** | 무왜곡 렌즈(수평 화각 70~78°)면 생략. 광각(1-3의 "80°~")이면 이미지 remap 대신 **키포인트 좌표만 undistort** | **OFF** | 1-3 | 생략 기준은 경험칙입니다. 왜곡은 화각뿐 아니라 렌즈 설계에 좌우되므로 선정한 카메라로 확인합니다. |
| **ROI 크롭** (원본 해상도에서) | 얼굴 bbox × 1.3–1.5 여유, 모델 입력 크기로 리사이즈(192–256px) | **ON** | 1-1, 1-7, 1-8 | **반드시 원본 해상도에서 크롭.** 전체 축소 후 크롭하면 입술 간격이 1–2px로 뭉개집니다. ROI 폭 확보 조건은 아래 참조 |
| **롤(roll) 정렬** | 양 눈 중심선이 수평이 되도록 ROI를 affine 회전 (±30° 이내) | **OFF** (ablation 후 결정) | 1-11, 5-6 | 사용할 랜드마크 모델이 롤에 이미 강건한지부터 확인합니다. |
| **ROI 대비 보정 (CLAHE)** | 휘도 채널(Y 또는 L)에만, clipLimit 1.5–3.0, tile 4×4 (얼굴 ROI 기준) | **OFF** (ablation 후 결정) | 2-2, 2-6 | **전체 프레임 적용 금지.** 입 주변 그림자(2-6)가 실제로 입벌림 오탐을 만드는지 확인한 뒤에만 도입합니다. |
| **감마 보정** | 얼굴 ROI 평균 휘도 < 90이면 γ 0.6–0.85, > 180이면 γ 1.1–1.3 (LUT) | **OFF** (ablation 후 결정) | 2-2, 2-3 | CLAHE보다 가벼워 둘 중 하나만 쓴다면 감마를 우선 검토합니다. |
| **노이즈 제거** | 기본은 카메라/ISP 내장 처리. 필요 시 ROI에 Gaussian 3×3, σ 0.5–1.0 | **OFF** | 2-3 | 시간축 잡음은 키포인트 스무딩으로 처리합니다. |
| **화이트밸런스 보정** | 생략 | **OFF** | 2-1 | 랜드마크 모델은 주로 휘도에 의존한다고 가정합니다. |
| **모델 입력 정규화** | 학습·INT8 양자화 보정(calibration) 데이터와 **완전히 동일한** mean/std, 채널 순서, 리사이즈 방식 | **ON (필수)** | 7-1 | 불일치하면 양자화 모델의 정확도가 급락합니다. |

### OFF 항목을 켜는 조건

- 같은 녹화 데이터에 on/off를 적용해 **점 지터, 편향, MAR 구분력**을 비교하고, 개선이 확인될 때만 켭니다.
- 추론 때만 CLAHE·감마를 적용하면 **학습 데이터와 입력 분포가 달라질 수 있습니다.** 도입한다면 학습 증강에도 같은 처리를 넣거나, 양자화 보정 데이터에 포함해야 합니다.

### ROI 폭 확보 조건

모델 입력(192px 이상)을 채우려면 원본 프레임에서 얼굴 ROI의 폭이 입력 크기 이상이어야 합니다.

`ROI 폭(px) = (W/2) / tan(HFOV/2) × 200mm / 거리`  (ROI 실제 폭 200mm 가정)

수평 화각 70° 기준입니다. 192px 이상이면 충분합니다.

| 해상도 | 50cm | 65cm | 80cm | 100cm |
|---|---|---|---|---|
| 1280×720 | 366 | 281 | 228 | 183 (부족) |
| 1920×1080 | 548 | 422 | 343 | 274 |

- 720p는 80cm까지 충분하고, 사용 거리가 더 멀어지거나 화각이 80°를 넘으면 1080p가 필요합니다.
- 어깨가 보이려면 50cm 거리에서 수평 화각이 약 62° 이상이어야 합니다. (어깨와 여유 폭 600mm 가정: 2 × 500mm × tan(62°/2) ≈ 600mm)
- 입력 해상도를 높이는 것은 연산 증가와 맞바꿈입니다. 센서 해상도가 ROI ≥ 입력을 만족하면 그 이상은 이득이 없습니다.

## 2. 키포인트 단위 전처리

### (a) 신뢰도 게이팅

- visibility 또는 score **< 0.5인 점은 결측으로 처리**합니다. (경험칙 시작값)
- 어깨는 화면 하단에서 자주 잘리거나 옷·긴 머리에 가려져 신뢰도가 낮을 수 있습니다. (1-8, 4-2, 4-4)
- 안경 반사나 두꺼운 테(4-1)가 눈 점을 흔들면 눈 점의 신뢰도가 떨어집니다. 이때 코·귀 등 다른 점으로 머리 pitch를 추정할지는 안경 착용자 데이터로 확인합니다.

### (b) 좌표 왜곡 보정

- 무왜곡 렌즈면 생략합니다. (1장)
- 광각이면 `cv2.undistortPoints`로 **필요한 점(눈, 입술, 턱, 어깨 등 20–30개)만** 보정합니다.
- 내부 파라미터를 모르면 `fx ≈ (W/2) / tan(HFOV/2)`로 근사하고, 제품 단위 체스보드 캘리브레이션을 1회 수행하는 것을 권장합니다.

### (c) 이상치 제거

세 가지를 조합합니다. (모두 경험칙 시작값)

| 방법 | 기준 |
|---|---|
| 속도 임계값 | 한 프레임 이동량이 어깨폭의 0.15–0.3배 초과 시 이상치. **30fps 기준이므로** 실제 처리 주기가 다르면 프레임 간격(dt)에 비례해 환산합니다. |
| Hampel 필터 | 창 5–7프레임, MAD 기준 k = 3. 정지 상태에서 MAD가 0이 되지 않도록 하한(예: 어깨폭의 1%)을 둡니다. |
| 구조 일관성 | 어깨폭·동공 간 거리가 베이스라인 대비 ±25% 이탈 시 해당 점 의심 |

- 연속으로 여러 프레임 거부되면 **실제 이동(레벨 시프트)**으로 보고 수용하는 규칙이 필요합니다. 없으면 빠른 정상 움직임 후 계속 거부됩니다.
- 카메라 흔들림(1-11)이 있으면 어깨폭·위치가 함께 변하므로 5장의 재캘리브레이션 트리거와 연결됩니다.

### (d) 결측 처리와 판정 보류

실시간 시스템이므로 양방향 보간은 지연을 만듭니다. 결측 길이에 따라 다르게 처리합니다.

| 결측 길이 | 처리 |
|---|---|
| ≤ 200ms | 마지막 값 유지 또는 등속 외삽 |
| 200ms – 2s | 판정 **보류**, 타이머는 리셋하지 않고 일시정지 |
| ≥ 2s | 해당 구간 무효 처리 및 상태 리셋 |

**판정 보류 조건** (PRD 2장)

| 조건 | 관련 체크리스트 | 비고 |
|---|---|---|
| 손·컵으로 얼굴 가림 | 5-4 | 입벌림 오탐의 주원인이므로 반드시 보류 |
| 얼굴 yaw가 정면 ±30° 초과 | 1-9, 5-2 | 고개를 돌리는 구간 |
| 영상 품질 불량 (1장 게이트) | 2-1, 2-3, 2-6 | |
| 점 결측 200ms~2s | – | |
| 자리 이탈 (얼굴·어깨 소실) | 5-7 | 2초 이상이면 리셋 |

### (e) 스무딩 — One Euro 필터 권장

정지 상태에서는 강하게, 움직일 때는 약하게 걸려 지연이 작습니다.

| 용도 | min_cutoff | beta | d_cutoff | 비고 |
|---|---|---|---|---|
| 거북목용 (어깨, 얼굴 윤곽·스케일) | 0.3–1.0 Hz | 0.001–0.01 | 1.0 | 느린 신호 → 강하게 |
| 입벌림용 (입술) | 1.0–2.0 Hz | 0.01–0.05 | 1.0 | 빠른 반응 필요 |

- **beta는 입력 좌표의 단위(픽셀 또는 정규화 좌표)에 따라 의미가 달라집니다.** 위 범위는 픽셀 단위 기준 시작값이며, 해상도가 바뀌면 다시 맞춰야 합니다.
- 이동평균 1초 창은 그 자체로 0.5초 지연을 만들기 때문에 쓰지 않습니다. 지연 정의는 PRD 3장(판정 확정 후 LCD 전환까지 ≤100ms)을 따르며, 판정 지속시간과는 별개입니다.

### (f) 기하 정규화 및 특징 계산

| 용도 | 원점 | 스케일 기준 | 대표 특징 |
|---|---|---|---|
| 거북목 | 어깨 중점 | 어깨폭 (별도로 강하게 스무딩) | 얼굴폭/어깨폭, (어깨선 y − 턱 y)/어깨폭, solvePnP 머리 pitch, 얼굴 절대 크기 |
| 입벌림 | 입 중심 | 입 너비 | MAR = 내측 입술 상하 간격(2–3쌍 평균)/입 너비 |

**입벌림의 pitch·yaw 영향**

- pitch 보정(÷cos pitch 근사)은 방향은 맞지만 **보정량이 작습니다.** 20°에서도 cos가 약 0.94로 6% 수준이고, 일반 3D 모델로 구한 solvePnP pitch는 오차가 수 도 이상일 수 있어 보정이 오히려 잡음을 더할 수 있습니다. **시제품 기본은 보정 없이 시작하고, ablation으로 이득이 확인되면 적용합니다.**
- yaw 30°에서 입 너비가 약 13% 줄어(cos 30° ≈ 0.87) MAR이 약 15%(1/0.87) 커질 수 있습니다. **yaw 허용 범위(±30°)를 두고 개인 임계값에 여유를 두는 것**으로 시작합니다.
- 치아 영역 밝기 비율은 선택 특징이며 시제품에서는 제외합니다.

**거북목의 구분 문제 (가설)**

- 카메라가 눈높이 이상에 있으면 거북목 상태에서 얼굴이 **내려가고 + 커지며 + 고개를 숙인 모양**이 될 것으로 예상합니다.
- 그러나 **상체 전체가 화면으로 다가오는 경우**(5-6)도 세 신호가 비슷하게 나올 수 있고, 구분하는 단서는 사실상 얼굴폭/어깨폭 비율뿐입니다. 정면에서 어깨 점은 가장 불안정한 점입니다. 이 구분이 실제로 되는지는 검증 대상입니다.

### (g) 거북목 점수 결합

- 베이스라인 대비 각 특징의 **robust z-score**(median/MAD)에 방향 부호를 곱해 가중 평균합니다.

| 특징 | 거북목 방향 |
|---|---|
| 얼굴폭/어깨폭 | 증가 |
| (어깨선 − 턱) 간격 / 어깨폭 | 감소 |
| 머리 pitch (숙임) | 증가 |
| 얼굴 절대 크기 | 증가 |

- 가중치는 처음엔 동일하게 두고, 측면 CVA 정답 데이터가 생기면 **상관이 높은 특징에 가중치를 주거나 회귀로 학습**합니다. (PRD 5.3 1차 목표)
- 카메라가 눈높이보다 낮아지는 경우 pitch의 부호가 달라질 수 있어 설치 위치를 제한했습니다. (PRD 5.4)

## 3. 거북목용 / 입벌림용 전처리 분리 여부

### 결론: 앞단은 공유하고, 평활화 이후 파라미터와 판정 로직부터 분리한다

시제품은 **얼굴 ROI 하나를 공유**하고(얼굴 랜드마크에서 입 점도 함께 얻음), 입 전용 ROI를 별도로 두는 것은 해상도가 부족하다고 확인될 때의 옵션으로 둡니다. (이전 안은 ROI 크롭부터 분리하는 구조였으나, 시제품 단순화를 위해 조정했습니다.)

### 분리가 필요한 이유

1. **스케일 처리가 정반대**
   거북목은 얼굴이 커지는 것 자체가 신호이고, 입벌림은 입 너비로 정규화해 그 변화를 없애야 합니다. 같은 정규화를 쓰면 한쪽이 망가집니다. (1-7 거리 변동)
2. **공간 해상도 요구가 다름**
   어깨·머리 위치는 저해상도로 충분하지만, 입술 간격은 픽셀 단위 정밀도가 필요합니다. (1장 ROI 폭 조건)
3. **조명 영향의 대상이 다름**
   입 주변 그림자(2-6)는 입벌림에 치명적입니다. 이미지 보정을 도입한다면 얼굴 ROI에만 적용합니다.
4. **시간 특성이 다름**
   거북목은 수십 초~수 분 단위의 느린 변화, 입벌림은 초 단위이며 말하기·하품·식사(5-5)와 구분해야 합니다. PRD의 시작값은 거북목 30초(30초~3분 조정), 입벌림 8초입니다. 스무딩 강도와 지속시간 판정을 따로 둡니다.

### 공유하는 부분

- 카메라 설정, 품질 게이트, 왜곡 보정, ROI 크롭, 랜드마크 추론, 이상치·결측 처리는 **공통**입니다.
- 머리 **pitch·yaw 값**은 거북목 특징이면서 입벌림의 보류 조건(yaw)이므로 양쪽에 전달합니다.

## 4. 최적 적용 순서 (파이프라인)

```
[S0] 카메라 설정: 전원 주파수 60Hz, AE 완만화 또는 잠금 검토
 │
[S1] 프레임 획득 + 타임스탬프
 │
[S2] 프레임 품질 게이트 (밝기·블러) ── 불량 → 판정 보류
 │
[S3] 축소 프레임에서 얼굴 위치 확보 (검출은 1–2초에 1회, 이후 이전 랜드마크로 추적)
 │
[S4] 원본 해상도에서 얼굴 ROI 크롭 (+ 롤 정렬: 선택)
[S5] ROI 감마/CLAHE: 선택 → 모델 입력 정규화
[S6] 얼굴 랜드마크 추론                         ※ 10–15fps
[S6b] 어깨 포즈: 얼굴 위치·크기 기준으로 상체 ROI를 크롭해 탑다운 추론   ※ 저주기 3–5fps
 │
[K1] 신뢰도 게이팅 (얼굴·어깨 점 모두)
[K2] 좌표 undistort (광각일 때만)
[K3] 이상치 제거 (속도·Hampel·구조 일관성)
[K4] 결측 처리 (유지/외삽 → 보류 → 리셋), yaw·가림 보류 판정
[K5] One Euro 스무딩 (점 그룹별 파라미터: 거북목용 / 입벌림용)
[K6] 정규화 + 특징 계산 ── 거북목: 어깨 기준 / 입벌림: 입 너비 기준
 │
 ├── 거북목 ──▶ [K7] 개인 기준 대비 편차 (z-score 결합)
 └── 입벌림 ──▶ [K7] 개인 임계값 대비 ──▶ [K8] 발화 필터
 │
[D1] 지속시간 + 히스테리시스 판정 → 알림 (쿨다운·스누즈·일일 상한)
```

- 탑다운 포즈 모델은 사람 영역을 크롭해서 넣어야 하므로, 어깨 추정(S6b)은 얼굴 위치(S3)가 확보된 뒤에 실행합니다. 얼굴 폭 대비 상체 ROI의 크기 비율은 PoC에서 정합니다.

### 순서가 바뀌었을 때 생기는 문제

| 잘못된 순서 | 생기는 문제 |
|---|---|
| 전체 프레임 축소 → 얼굴 크롭 (S4를 S3 축소본에서 수행) | 입술 간격이 1–2px로 양자화되어 MAR 해상도 소실 |
| CLAHE를 크롭 전 전체 프레임에 적용 | 창문 역광·모니터 빛이 타일 통계를 지배해 얼굴 대비가 오히려 악화, 연산량도 증가 |
| 롤 정렬 전 CLAHE | 회전 보간 과정에서 경계에 계단 현상이 생길 수 있음 (영향은 작을 것으로 예상, 정렬 먼저가 정석) |
| 스무딩(K5) → 이상치 제거(K3) | 튄 값 하나가 수 프레임에 번져 이상치 검출 불가, 그 사이 오탐 발생 |
| 보간(K4) → 이상치 제거(K3) | 이상치를 근거로 보간값을 만들어 오류 확대 |
| 정규화(K6) → undistort(K2) | 가장자리 어깨 좌표 왜곡이 스케일 기준(어깨폭)에 섞여 모든 비율 특징이 틀어짐 |
| 베이스라인(K7)을 스무딩 전에 계산 | 베이스라인 자체가 잡음을 포함, 통계가 실제 추론 신호와 불일치 |
| 발화 필터(K8) 없이 판정 | 통화·회의 중(5-1, 5-5) 입벌림 알림 연발 → PRD 오탐 목표(≤3%) 위반 |

## 5. 개인 캘리브레이션과 적응

### 위치

- **K6(특징 계산) 직후, 판정 직전인 K7**에 넣습니다.
- 베이스라인은 반드시 **추론 때와 똑같은 S0–K6 파이프라인을 통과한 특징값**으로 만들어야 합니다.

### 캘리브레이션 절차 (PRD 2장)

| 단계 | 내용 |
|---|---|
| 설치 검증 | 얼굴 위치, 정면 정도(yaw), 어깨 가시성이 허용 범위 안인지 확인. 벗어나면 캘리브레이션 대신 위치 재조정 안내 |
| 카운트다운 | 약 3초 (AE 수렴과 자세 정착 시간을 겸함) |
| 중립 촬영 | 바른 자세 + 입 다묾 약 10초 (앞 1초는 추가로 버림: 시작값) |
| 입 벌림 촬영 (선택) | 의도적으로 살짝 벌린 상태 3–5초. 두 상태의 중간값을 개인 임계값으로 사용 |
| 품질 검사 | 움직임 분산이 크거나 유효 표본이 부족하면 **재촬영 요청** |

- 이전 안(30초)보다 짧아져 표본이 줄므로, 통계는 평균·표준편차 대신 **median과 MAD**로 계산하고, 유효 표본 수의 최소 기준(얼굴 랜드마크 10–15fps 기준 약 60–100개, 시작값)을 둡니다.
- AE 잠금 방식을 쓴다면 이 시점에 잠금합니다. (이 단계만 예외적으로 이미지 단위 캘리브레이션)
- 입 주변 특성(수염, 립 메이크업, 교정기, 평상시 벌어진 입술: 4-3)은 개인차가 커서 고정 임계값이 맞지 않으므로 입 다문 상태를 별도로 확보합니다.

### 한계: "바른 자세"를 보장할 수 없다

- 거북목 습관이 있는 사용자는 캘리브레이션 때도 구부정할 수 있고, 정면 영상으로 바른 자세인지 **직접 판정할 수 없습니다.**
- 완화책: 어깨선 수평, 얼굴 정면(yaw·roll이 작음) 같은 **간접 품질 검사**와 화면 가이드를 제공하고, 한계를 사용자에게 안내합니다.
- 6-4(바른 자세 기준 촬영)는 이 방식의 전제입니다.

### 사용 중 적응 (PRD 2장 7)

| 적응 대상 | 방식 | 허용 |
|---|---|---|
| 입 다문 상태의 MAR 분포, 발화 패턴 | 사용 중 통계(median/MAD) 갱신 | ✅ |
| 민감도, 판정 기준 시간 | 사용자 피드백(오탐 신고, 알림 후 반응)에 따라 **허용 범위 안에서** 조정 | ✅ |
| 조명·카메라 이동 | 감지 시 재캘리브레이션 **제안** | ✅ |
| **기준 자세 자체** | **자동 갱신 금지.** 사용자가 명시적으로 재캘리브레이션할 때만 갱신 | ❌ |

- 기준 자세를 자동 갱신하면 습관화된 나쁜 자세를 정상으로 학습하게 됩니다.
- 이것은 모델 재학습이 아니라 통계 갱신입니다.
- **시제품 범위**: 피드백 입력에는 PC 컴패니언 앱이 필요하므로, 시제품은 첫 번째 행(입 MAR 분포, 발화 패턴의 통계 갱신)만 적용하고 피드백 기반 조정은 제외합니다. (PRD 5.3)

### 재캘리브레이션 트리거

- 어깨폭이나 어깨 위치가 일정 시간 동안 베이스라인에서 크게 벗어나 있는데 자세 변화로 설명되지 않으면 카메라가 움직였다고 보고 재촬영을 **제안**합니다. (1-11, 1-6)
- 이탈 기준과 지속 시간은 시작값(예: 어깨폭 ±25%, 위치 이동 어깨폭의 0.6배, 60초)으로 두고 사용자 테스트로 정합니다.

## 6. NPU 성능을 고려한 생략 및 경량화

> 칩이 미확정이므로 **실측으로 결정**합니다. 카탈로그의 TOPS는 실효 성능이 아닙니다. 공개 벤치마크 1건(RV1126, yolov5s INT8 640px 20fps)으로 계산한 실효 활용률은 카탈로그 값의 약 15% 수준이었고, 이 값은 추정입니다. 계산에 쓴 yolov5s의 연산량(약 16.5 GFLOPs)은 검색으로 확인한 값이 아니라 **기억에 의존한 값**이므로 확인이 필요합니다.

### 생략 (시제품 기본 OFF)

| 단계 | 대체 방법 |
|---|---|
| 전체 프레임 디노이즈 (Bilateral·NLM) | 카메라 내장 처리 + 키포인트 스무딩 |
| 전체 프레임 왜곡 보정 remap | 키포인트 좌표만 undistort (광각일 때) |
| 화이트밸런스 보정 | 생략 |
| 전체 프레임 CLAHE | 도입한다면 얼굴 ROI 한정 |

### 경량화

- **실행 주기 분리**: 포즈 3–5fps (거북목은 느린 신호), 얼굴·입 랜드마크 10–15fps. 처리 주기는 시작값이며 실측으로 조정합니다. 12fps이면 프레임 간격만 약 83ms이므로 PRD 지연 정의(판정 확정 후 LCD 전환)와 구분해서 측정합니다.
- **검출 대신 추적**: 얼굴 검출은 1–2초에 1회 또는 추적 실패 시에만 실행하고, 나머지 프레임은 이전 랜드마크로 ROI를 갱신합니다.
- **카메라 출력 포맷**: USB 카메라는 MJPEG 디코딩이 CPU 부담이 될 수 있으므로 720p@30fps로 운용하고 디코딩 비용을 실측합니다.
- **필요한 점만 처리**: undistort·스무딩은 사용하는 16–30개 점에만 적용합니다.

### 모델 후보와 선정 기준 (PRD 4장)

| 역할 | 후보 | 확인된 수치 | 비고 |
|---|---|---|---|
| 포즈(어깨) | RTMPose-t / -s | 0.36 / 0.68 GFLOPs (256×192), COCO AP 68.5 / 72.2 | 탑다운 방식이라 얼굴 추적으로 얻은 위치로 크롭하면 사람 검출기가 불필요 |
| 포즈 (대안) | YOLOv8n-pose | 9.2 GFLOPs (640px) | 사람 검출을 포함한 범용 모델이라 단일 사용자에게는 과함. RV1126·RV1106에서의 지원은 확인하지 못함 |
| 얼굴 랜드마크 | PFLD 계열 | 0.25X 2.1MB / 1X 12.5MB | **입술 내측 점을 내는지**가 필수 조건 |

- RKNN 변환 가능 여부와 INT8 후 정확도는 **전부 미검증**입니다.
- **선정 기준은 정확도 우선**입니다. 목표 환경(정면, 착석, 실내)에서 점의 **지터와 편향**, FP32 대비 INT8 오차를 먼저 평가하고, 지연과 연산 예산을 만족하는 모델 중 가장 정확한 것을 고릅니다. 공개 벤치마크 점수는 우리 환경의 정확도를 보장하지 않습니다.
- 입벌림에서 중요한 것은 편향입니다. 입술 5mm 간격은 60cm, 720p, 화각 70° 가정에서 약 7.6px인데, 경량 랜드마크 모델의 한 프레임 오차가 이와 비슷한 크기일 수 있습니다. 무작위 오차는 시간 평균과 개인 베이스라인이 줄여주지만 **편향은 줄이지 못합니다.**
- 차선책: 연산이 부족하면 얼굴 랜드마크에서 직접 pitch·스케일을 얻고 어깨는 저주기 포즈로만 보완합니다.

## 7. 체크리스트 매핑 및 검증 항목

### 체크리스트 응답이 설계에 미치는 영향

[check_list.md](check_list.md)는 응답이 비어 있습니다. 시제품에서 **응답이 설계를 바꾸는 항목**과 현재 가정은 다음과 같습니다.

| 항목 | 설계에 미치는 영향 | 시제품 가정 | 응답이 가정과 다르면 |
|---|---|---|---|
| 0 환경 유형 (사무실, 가정 등) | 환경별 파이프라인 분기 여부 | 단일 파이프라인 | 환경별 편차가 크면 품질 게이트·적응 파라미터를 환경별로 분기 검토 |
| 1-1 해상도, 1-2 FPS | ROI 폭, 스무딩·이상치 파라미터 | 720p@30fps | 1장 ROI 폭 표와 One Euro·속도 임계값 재설정 |
| 1-3 FOV | undistort 필요 여부, 어깨 가시성 | 수평 70~78°, 왜곡 보정 생략 | 광각이면 keypoint undistort ON |
| 1-4 설치 위치, 1-9 모니터 구성 | 기본 yaw 오프셋, 보류 빈도 | 상단 중앙, 단일 모니터 | 오프셋은 캘리브레이션이 흡수하나 yaw ±30° 초과 시 보류가 잦아짐 |
| 1-5 카메라 높이, 1-6 틸트 | pitch 부호와 특징 방향 | 눈높이 이상 | 눈보다 낮으면 2장 (g)의 부호 재설계 (PRD 5.4: 지원 범위 제외) |
| 1-7 거리 | ROI 폭, 얼굴 크기 기준 | 50~80cm | 범위가 넓어지면 해상도·ROI 재계산 |
| 1-8 상반신 범위 | 어깨 특징 사용 가능 여부 | 어깨까지 보임 | "얼굴만"이면 거북목 특징을 얼굴 크기와 pitch로 제한 |
| 1-10 자동 설정, 2-4 조명 변화, 2-5 플리커 | AE 설정, 품질 게이트 | AE 완만화/잠금, 60Hz | 조명이 급변하면 재캘리브레이션 제안 빈도 증가 |
| 1-11 고정 상태 | 재캘리브레이션 트리거 | 단단히 고정 | 흔들리면 이상치·트리거 기준 재조정 |
| 2-1 광원 종류 | 화이트밸런스 보정, 플리커 대응 | WB 생략 (형광등·LED 혼재 가능) | 모니터 푸른빛이 크면 WB 필요성 재검토 (OFF 항목, ablation) |
| 2-2 광원 방향, 2-3 밝기, 2-6 반사·그림자 | 감마·CLAHE 도입 여부 | 모두 OFF | 그림자가 입벌림 오탐을 만들면 ROI 한정 도입 (ablation) |
| 3-1 배경 복잡도, 3-3 배경·의상 대비 | ROI 크롭 우선 적용, 어깨 윤곽 신뢰도 | 얼굴 ROI 크롭으로 대응, 어깨 신뢰도 게이트 | 대비가 낮아 어깨 점 신뢰도가 자주 낮으면 거북목 판정 보류가 잦아지므로 임계값 또는 대체 특징 검토 |
| 3-2 배경 움직임 | 주 사용자 추적, 다중 인물 처리 | 단일 사용자 | 다른 사람이 자주 잡히면 가장 큰 얼굴/중앙 얼굴 선택 로직 추가 |
| 4-1 안경, 4-2 가림 | 눈·어깨 점 신뢰도, 결측 처리 | 두꺼운 반사 안경은 별도 검증 | 안경 반사가 크면 눈 대신 코·귀 보조점 검토 |
| 4-3 입 주변 특성 | 개인 임계값 필요성 | 개인 임계값 사용 | – |
| 4-4 목 의상 | 턱·어깨선 가림 | 우리 특징은 목 윤곽을 쓰지 않아 직접 영향은 작다고 가정 | 후드·스카프로 어깨선이 가려지면 결측이 늘어 판정 보류가 잦아짐 |
| 4-5 피부톤 | 평가 데이터 다양성, 노출 범위 | 평가 데이터에 다양한 피부톤 포함 | 특정 집단에서 성능이 떨어지면 데이터 보강 |
| 5-1 작업 유형, 5-5 입 움직임 | 발화 필터 강도, 상황별 임계값 | 단일 임계값 | 화상회의가 잦으면 발화 필터 강화 |
| 5-2 고개 회전, 5-3 고개 숙임 | yaw 보류 빈도, 판정 시간 | 정면 ±30°, 거북목 30초 | 숙임이 잦으면 판정 시간을 늘림 |
| 5-4 손 가림 | 보류 규칙 | 가림 시 보류 | – |
| 5-6 몸통 자세, 5-7 자리 이탈, 5-8 착석 시간 | 거북목/상체 이동 구분, 리셋 규칙, 장기 드리프트 | 2장 (f) 가설 | 상체 이동이 잦으면 구분 로직 재검토 |
| 6-1 거북목 정답, 6-2 입벌림 라벨, 6-3 라벨링 방식, 6-4 기준 촬영 | 평가 체계 (PRD 3장) | 측면 보조 카메라 CVA, 입술 내측 간격 라벨 | **최우선 확정 항목** |
| 7-1 추론 위치 | 연산 예산, 전처리 무게 | 온디바이스 (PRD 확정) | – |
| 7-2 원본 저장 허용 | 평가 데이터 수집 방식 | 미정 | 키포인트만 저장하면 이미지 단위 비교 실험 불가 |
| 7-3 허용 지연, 7-4 민감도 | 판정 시간, 오탐 우선순위 | PRD: 지연 ≤100ms, 오탐 ≤3% (정밀도 우선) | 응답이 다르면 PRD와 대조 |

### 우선 검증 항목 (PRD 7장과 연결)

1. 🔴 **정면 간접 신호와 측면 CVA의 상관** (6-1): 측면 보조 카메라를 동기 촬영해 확인합니다. 실패하면 2장 (g)와 PRD 5.1-1을 재정의합니다.
2. 🔴 **후보 모델의 INT8 변환 가능 여부와 정확도** (6장): 점 지터, 편향, FP32 대비 오차, 입술 내측 점
3. 🔴 **목표 SoC의 실측 지연과 연산 예산**: 포즈 3–5fps, 얼굴 10–15fps 가정의 검증
4. 🟠 **체크리스트 응답 수집**: 위 표의 1-3, 1-5~1-7, 2-x, 4-x, 5-x. 거리·높이·화각은 정확한 값이 아니라 범위만 알아도 설계가 가능합니다.
5. 🟠 **이미지 보정(OFF 항목)의 도입 필요성**: 같은 녹화에 on/off를 적용해 비교합니다.
6. 🟡 **입벌림 라벨 기준의 수치화** (6-2): "입 너비 대비 비율 ≥ X%가 Y초 이상"처럼 정량화하고 발화·하품·식사의 라벨 처리 규칙을 정합니다.
7. 🟡 **조사 규모**: 베이스라인 방식이 사람 간 편차를 얼마나 흡수하는지 검증하려면 습관이 있는 사용자를 포함해 다양한 조명 조건에서 충분한 이벤트(PRD 3장 기준 약 300건)가 필요합니다.
