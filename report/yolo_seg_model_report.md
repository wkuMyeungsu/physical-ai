## 1. 적용 모델

### 1.1 선정 모델

| 역할 | 모델 | 학습 | 상태 |
|---|---|---|---|
| 거북목: 얼굴·상체 영역 분할 | **YOLO-seg** (face, upper_body 2클래스, nano부터) | 직접 파인튜닝 | 3장 ~ 4장 |

### 1.2 거북목 신호의 가설

고개가 앞으로 나오면 정면 영상에서 얼굴이 커지고 아래로 내려가 턱이 어깨선 쪽 `upper_body` 영역과 겹칩니다. `face ∩ upper_body` 면적 / `face` 면적(겹침 비율), 얼굴 너비 / 상체 너비, 두 영역 사이 세로 간격을 신호로 쓰고, 개인 기준(10초 영점) 대비 편차로 판정합니다. 이 가설은 V1b의 CVA 상관 실험으로 먼저 확인합니다.

거북목 판정에 쓰는 간접 신호는 다음과 같습니다: 얼굴폭/어깨폭 비율, 턱-어깨선 간격, 머리 pitch, 얼굴 크기 변화, 얼굴·몸통 마스크 겹침 비율. 신호별 타당성은 V1b에서 확인합니다.

### 1.3 제외 모델과 미확인 사항

- **YOLO-pose는 제외**: 범용 다인 모델이라 단일 사용자에게는 연산이 과합니다.
- **미확인**: YOLO-seg의 RKNN 변환 가능 여부와 보드 연산량(마스크 출력부로 연산이 늘어남). V2~V3에서 확인합니다.

## 2. 모델 크기와 입력 크기

### 2.1 모델 크기

- **시작 모델**: COCO 사전학습 `nano-seg`.
- **이유**: 보드(RK3566급)에서 상체 분할을 3~5fps, 지연 **≤100ms**로 돌려야 하고, NPU를 얼굴 랜드마크(10~15fps)와 나눠 씁니다. 클래스가 2개이고 대상이 크게 찍혀(3.2 기준값) nano 용량으로 충분할 가능성이 큽니다.
- **small 조건**: E3에서 정확도와 보드 지연을 함께 볼 때만 검토합니다. 실험 계획은 3.4를 참조합니다.

### 2.2 입력 크기 (imgsz)

- **시작값**: `imgsz=640`. E5에서 더 작은 값과 비교합니다.
- **이유**: 640에서도 얼굴이 85px 이상이라 크기 때문에 놓칠 걱정은 없습니다. 줄이면 보드 지연은 줄지만, 마스크(입력의 약 1/4 해상도) 한 칸이 60cm에서 약 0.5cm → 320이면 약 1cm로 커져 턱과 상체 겹침 경계가 거칠어집니다. V3 지연과 함께 판단합니다.
- 얼굴·어깨 크기 계산 근거는 3.2를 참조합니다.

## 3. 학습 모델과 학습 방식

### 3.1 데이터와 라벨링

- **데이터 출처**: 웹캠 정면 상반신 공개 데이터셋 중 라이선스·라벨 형식을 확인한 것을 선별해 쓰고, 부족한 조건은 직접 촬영해 보강합니다. 주 평가는 직접 촬영 데이터로 합니다(제품 조건과 같기 때문).
- **직접 촬영 조건**: 조명(밝음/형광등/어두운 실내), 안경 유무, 자세(바른 자세 / 약한 거북목 / 강한 거북목 / 손·컵 가림), 거리(50·65·80cm), 카메라는 모니터 상단 눈높이 이상. 같은 조건의 수천 장보다 조건이 다른 장면을 우선합니다.
- **규모(시작 목표)**: 1차로 약 600장 라벨링, 사람 약 10명. 부족하면 학습 곡선과 진단(4.3)을 보고 어떤 조건을 더 모을지 정합니다.
- **분리**: 학습/검증/테스트를 **사람 단위**로 나눕니다(예: 테스트는 학습에 없는 2~3명). 테스트는 마지막 비교에만 씁니다.
- **라벨 기준**: `face`는 이마~턱, `upper_body`는 **머리를 제외한** 어깨선~가슴 영역. 목 경계 규칙을 문서화해 모든 라벨에 동일 적용하고, 라벨링 중간(100장)에 같은 이미지를 다시 라벨링해 일관성을 점검합니다.
- **도구**: Roboflow Smart Polygon(SAM 기반). 약 100장 라벨링 → 1차 학습 → 모델 초안 윤곽을 사람이 보정. 무료 크레딧 한도와 이미지당 소모량은 사용 전 확인합니다.
- **정답 데이터(CVA)**: 평가용 촬영에서는 측면 보조 카메라를 동기 촬영합니다.
- **제품 입력 조건** (학습·평가 데이터가 맞춰야 할 조건):
  - 카메라 720p@30fps 운용, 수평 화각 약 70~78°, 저왜곡 렌즈
  - 모니터 상단 중앙 설치, 카메라는 눈높이 이상
  - 사용 거리 50~80cm (가정값, 현장 확인 필요)
  - 얼굴 정면 ±30° 이내 (벗어나면 판정 보류)
  - 마스크, 모자, 역광 창문은 제품 지원 범위 밖이므로 학습·평가 데이터의 대상이 아닙니다.

### 3.2 학습 기준값

600장·10명을 사람 단위로 학습 6 / 검증 2 / 테스트 2명으로 나눈다고 가정하면 학습은 약 360장, 배치 16일 때 에폭당 약 23회 반복입니다. 1280×720 영상을 640으로 줄이면 얼굴 너비는 60cm에서 약 115px, 80cm에서 약 85px, 어깨 너비는 80cm에서도 약 230px입니다(화각 70° 가정). 아래 학습 설정의 이유는 이 값을 근거로 합니다.

### 3.3 학습 설정

| 항목 | 결정 | 이 프로젝트에서의 이유 |
|---|---|---|
| 프리징 | `freeze=10`으로 시작, E2에서 `None`과 비교. 단계적 해제는 E2에서 `None`이 확실히 나을 때만 검토 | 학습 데이터가 약 6명이라 백본까지 풀면 그 6명의 얼굴·옷·방을 외울 위험이 큼(테스트는 처음 보는 사람). 반대로 `upper_body`는 **머리를 뺀 어깨~가슴**이라 COCO의 person(전신)에 없는 목 경계를 새로 배워야 해서, 얼린 백본으로 부족한지 E2로 확인. 레이어 번호는 검출 모델 기준이라 seg 모델 구조를 출력해 확인한 뒤 적용 |
| 옵티마이저·학습률 | `optimizer=AdamW`, `lr0=0.001` 고정, `warmup_epochs` 3·`lrf` 기본 | `auto`는 총 반복 수로 옵티마이저를 고름. 지금(약 6,900회)은 AdamW·lr 약 0.0017이지만, 데이터를 보강해 1만 회를 넘으면 **SGD·0.01로 바뀌어** 실험 간 비교가 깨짐. 0.001은 auto 값보다 약간 낮춰 E2의 `freeze=None`에서도 COCO 특징이 덜 흔들리게 함 |
| 배치 | E0에서 `batch=-1`로 자동 산정값을 확인하고, E1부터 그 값으로 고정 | Colab 무료는 세션마다 배정 GPU가 달라질 수 있어 자동 배치가 실험마다 바뀌면 비교가 깨짐. 배치는 위 반복 수와 auto 판정에도 영향을 줌 |
| 에폭·조기 종료 | `epochs=300`, **`patience=30`** | 에폭당 약 23회 반복이라 300에폭이어도 약 6,900회로 짧음. val이 약 2명(약 120장)뿐이라 점수가 에폭마다 출렁여 10~20이면 출렁임에 일찍 멈출 수 있고, 기본 100이면 E0~E5 반복에 Colab 사용 시간을 낭비 |
| 증강 | `mosaic` 0.5 vs 0(E4), `multi_scale` 끔, 나머지(`scale`·`hsv_v`·`fliplr`) 기본 | 제품 화면은 **한 사람이 가운데 크게** 찍히는데 모자이크는 작은 사람 4명을 만들고 어깨·목 경계를 이미지 가장자리에서 자름. 720p 고정이라 `multi_scale`은 불필요하고, 50~80cm 거리 차(얼굴 크기 약 1.6배)는 기본 `scale`(±50%)이 덮음. 조명은 직접 촬영 3조건 + 기본 밝기 변화, 좌우 반전은 좌우 구분 클래스가 없어 무방 |
| 비교 지표 | val **마스크** mAP50-95, `upper_body` AP 별도 | 거북목 신호인 겹침 비율(`face ∩ upper_body` / `face`)은 턱 부근 경계 몇 px에 좌우됨. IoU 0.5만 넘으면 맞다고 치는 mAP50으로는 이 차이가 안 보임. `upper_body`는 목 경계가 모호해 따로 봄. 결과가 나쁠 때는 4.3 |
| 불균형·망각 | 대응 안 함(`cls_pw` 미사용) | 단일 사용자 제품이라 이미지마다 face·upper_body가 정확히 1개씩(1:1)이고, COCO의 다른 클래스는 제품에서 쓰지 않음 |
| 학습 환경 | 실험(E0~E5)은 **Colab**, Roboflow 학습은 라벨링 보조용 1차 모델에만 | Roboflow 학습은 freeze·lr·mosaic 같은 세부 설정 지정이 제한적이라 E2·E4 비교를 할 수 없음(지원 범위는 사용 전 확인). 로컬 GPU가 없어 Colab 무료 GPU를 씀 |
| 재현성 | `seed=0`, `deterministic=True` | val이 작아 실험 간 차이가 시드 운과 비슷할 수 있음. 차이가 작으면 시드를 바꿔 한 번 더 돌린 뒤 판단 |
| 캐시·AMP | `cache='ram'`, AMP 기본 | 약 360장(640 기준 수백 MB)은 Colab RAM에 충분하고, Drive에서 매 에폭 읽는 시간을 없앰. 배포가 RKNN INT8이라 학습을 FP32로 고집할 이유가 없고 변환 손실은 V2에서 따로 잼 |

파인튜닝은 출시 전 오프라인 작업이며, 사용 중 개인 적응은 재학습이 아니라 통계 갱신입니다.

### 3.4 실험 계획

같은 데이터·시드에서 한 번에 하나만 바꿔 비교하며, `fraction`이 아닌 전체 소규모 데이터로 돌립니다. 순위만 보고 다음 실험을 정합니다.

| 실험 | 비교 | 판단 기준 |
|---|---|---|
| E0 점검 | 학습 전 `val` 한 번, 소량(`fraction`)으로 설정 확인, 자동 배치값 확인 | 라벨 경로 오류(라벨 0개) 방지. `fraction` 점수는 순위로만 참고 |
| E1 기준 | nano-seg, freeze=10, 3.3 설정 | 이후 실험의 비교 기준 |
| E2 프리징 | freeze=10 vs freeze=None | val 마스크 mAP50-95와 학습 곡선 |
| E3 크기 | nano vs small (E1이 정체될 때만) | 올려도 안 오르면 데이터 보강으로 |
| E4 증강 | mosaic 0.5 vs 0 | val 마스크 mAP50-95 |
| E5 해상도 | imgsz 640 vs 더 작은 값 | V3 보드 지연과 함께 판단 |

## 4. 검증 방법

### 4.1 단계별 검증

| 단계 | 무엇을 | 어떻게 | 통과 기준 |
|---|---|---|---|
| V1a | 영역 정확도 | 테스트 사람의 마스크·박스 mAP50, mAP50-95, **클래스별 AP**(face와 upper_body를 따로) | upper_body AP는 경계가 모호해 face보다 낮을 수 있어 따로 봄. 수치는 결과를 보고 확정 |
| V1b | **신호 타당성(CVA 상관)** | 참가자마다 바른 자세 / 약한 / 강한 거북목을 각 10초 정면 + 측면 동기 촬영. 측면 영상에서 CVA를 재고, 정면에서 얻은 신호(겹침 비율, 너비 비율, 간격)의 **개인 기준 대비 변화량**과 비교해 사람별 순위 상관을 봄 | 대부분의 참가자에게서 같은 방향으로 움직일 것. 실패 시 신호 정의를 다시 세움 |
| V2 | 변환 손실 | ONNX로 내보내 RKNN INT8 변환을 시도하고, 같은 테스트 영상으로 FP32 대비 mAP·마스크 IoU 하락 비교 | 하락이 V1a 허용 범위 안. 변환 불가 시 대안 모델 검토 |
| V3 | 보드 성능 | 개발 보드에서 해상도별 지연·연산량 실측 (카탈로그 TOPS 아님) | 지연 ≤100ms, 3~5fps |
| V4 | 제품 정확도 | 참가자별 연속 작업(음료, 대화, 손 가림 포함) 영상에서 이벤트 단위 Precision/Recall, 오탐율. 정답 이벤트는 측면 CVA가 개인 기준 대비 일정 각도 이상 낮은 상태가 30초 이상 지속된 구간(각도는 V1b의 CVA 분포를 보고 정함) | 제품 목표 수치 (시제품 단계는 측정 체계 구축이 1차 목표) |
| V5 | 판정 보류 | 가림·화질 불량 구간에서 오판정 대신 보류했는지, 보류가 너무 잦지 않은지 | 보류 비율과 오탐 감소를 함께 보고 기준 설정 |

V1 → V2 → V3 순으로 앞 단계가 싸고 빠르므로 먼저 통과해야 다음으로 갑니다. 알림이 발생하면 해당 프레임을 저장해 오탐 원인을 라벨링합니다. 정상/거북목을 가르는 CVA 기준 각도는 문헌 값을 확인해 정합니다.

### 4.2 지표 기준

V1~V5는 제품 지표(이벤트 단위 정확도, 오탐율, 지연)를 측정하기 위한 단계입니다. 목표 수치 자체는 이 보고서에서 정하지 않으며, 평가 데이터는 사람 단위로 나눈 데이터를 씁니다(3.1).

### 4.3 결과가 나쁠 때의 진단

| 증상 | 의미 | 대응 |
|---|---|---|
| 아무것도 안 잡힘 | 경로·라벨 문제 | `data.yaml` 경로, 클래스 번호 범위, 신뢰도 임계값 순으로 확인 |
| upper_body AP만 낮음 | 몸통 경계 라벨이 일관되지 않음 | 목 경계 규칙 재정의, 일관성 점검 후 재라벨링 |
| mAP50 높음 · mAP50-95 낮음 | 영역은 찾지만 윤곽이 대충임 | 라벨 윤곽 정밀화, 더 오래 학습 |
| 어두운 조명·안경에서만 Recall 낮음 | 그 조건 데이터 부족 | 해당 조건 촬영 추가 |
| 정상 행동(음료·손 가림)에서 오탐 | 헛경고 | 후처리 기준 시간·임계값 강화, 해당 장면 데이터 추가 |
| 얼굴이 작아 사라짐 | 입력 해상도 부족 | 해상도를 올리고 배치를 줄임(V3 확인) |
| mAP 높음 · CVA 상관 낮음 | 모델은 맞지만 신호가 거북목을 반영하지 못함 | 겹침 대신 너비 비율 등으로 신호 재정의 |
| 전반적으로 낮음 | 학습 부족 또는 라벨 품질 문제 | 에폭 증가, 데이터 양과 라벨 품질 점검 |
